# 领域文档

## 文档布局

本仓库采用单一领域上下文：

- 术语表：`knowledge/GLOSSARY.md`。
- 架构决策索引：`knowledge/adr/README.md`。
- 架构决策记录：`knowledge/adr/`。

以上现有路径是领域文档的权威位置。
使用 domain-modeling 技能时，将已确定的术语和决策写入这些位置。

## 探索代码库前

阅读 `knowledge/GLOSSARY.md`，再阅读架构决策索引及与当前工作相关的决策。

若文档不存在，直接继续工作。
通过 domain-modeling 明确术语或决策后，再创建相应文档。

## 术语使用

问题标题、方案、假设和测试名称均使用术语表中的定义，
并遵守其中对易混淆表达的约束。

若所需概念尚未收录，先判断它是否属于本项目的领域；
确有缺口时，记录下来供 domain-modeling 补充。

## 架构决策冲突

方案若与已接受的架构决策冲突，应明确指出对应 ADR，
并说明重新考虑该决策的原因。
