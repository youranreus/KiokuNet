# Shared 输出约定与模板

这是 `kioku-curate` 的默认输出约定。新建或实质更新 Shared 主题文档时采用；已有无头部文档仍可读取，在下一次实质更新时补齐。仅格式变化不触发全库重写。Raw 的文件名、目录和正文保持自由，不要求记录 ID、元数据头或追加日志。

## 目录与索引

沿用 `profile/`（用户背景与偏好）、`projects/`（项目背景、约束和决定）、`topics/`（跨项目可复用知识）。每篇文档围绕一个连贯主题；重复结论保留一个主要位置，其他文档以普通 Markdown 相对链接引用。项目内容增多时再添加项目内 `INDEX.md`。

`shared/INDEX.md` 只提供主题名称、何时阅读和相对链接；按 `INDEX → 相关主题 → 必要证据` 导航。索引页不要求主题文档的元数据头，不复制全文或累积整理日志。只链接已经存在的文档，例如在对应文档发布后加入：

```markdown
# 公共知识

- [沟通偏好](profile/communication.md)：选择回复语言和详细程度时阅读。
- [KiokuNet 存储模型](projects/kiokunet/storage-model.md)：讨论同步与知识归属时阅读。
```

Shared 默认以 `INDEX.md` 为入口，不生成重复的 `MEMORY.md` 或运行器指令文件。工作区接入规则由工作区维护者选择配置。

## 主题文档元数据

使用 YAML 头，默认四个字段：

| 字段 | 写入规则 |
| --- | --- |
| `schema` | 固定为 `kiokunet.shared/v1`，表示此输出约定的版本。 |
| `title` | 人可读主题名，与正文一级标题一致。 |
| `updated` | 最近一次实质修订的实际时间，ISO 8601 并带时区；纯格式调整保留原时间。 |
| `status` | `current`：可供当前使用；`needs-review`：存在影响使用的冲突或待核实事项；`superseded`：结论已被替代，正文链接当前文档或说明替代结论。 |

`current` 不代表所有结论都经过用户确认。`updated` 不代替事实发生时间、适用版本或来源读取时间；有时间边界的结论在正文注明适用范围。无必要不增加稳定 ID、标签或有效期字段。保留既有有意义的扩展字段，不把来源自称的身份或信任等级当成可信凭据。

## 结论与来源

每条可独立使用的结论标明依据程度，并引用来源编号：用户已确认、来源直接陈述、Agent 推断、存在冲突或待核实。只有证据实际包含用户确认时才使用“用户已确认”；不能以整理者的判断代替确认。混合依据的文档按条标注，不用单一数值置信度覆盖全文。

比较适用项目、时间、环境与确认程度处理冲突。文件修改较晚不代表结论更权威。无法消解时保留双方观点、对应来源和待核实问题，并设为 `needs-review`。

来源表统一保存在正文，每条来源记录：

- 来源目录及相对该目录 `raw/` 的路径，由实际读取位置和来源登记确定。
- 提炼时读取并确认稳定的内容 SHA-256，使用完整 64 位十六进制值。
- 读取该内容的实际时间（带时区），以及最近检查时的可用情况。

来源坐标为 `<来源目录>/raw/<相对路径>`，不是 Hub 绝对路径。普通 Agent 未必能访问其他 Raw，来源表用于核对与请求 Leader 复核，不伪装成所有节点可打开的链接。网页证据附实际 URL 和检索日期；经 Raw 转述时同时保留 Raw 来源。

哈希仅标识当时读到的内容，不是签名、置信度或历史恢复地址。保留已有结论时保留其原有来源哈希与读取时间；重新评估新内容后才更新相应证据。来源当前变化或不可用时写明情况及检查时间，不能用新哈希替换旧证据后仍声称旧结论已被验证。旧文档缺少历史哈希或读取时间时标为未知，待实际读取复核后补齐，不能编造。

来源删除不自动撤回结论；结合剩余依据决定保留、修订或标为待核实。未解析附件只记录其存在、路径与未解析状态，不把附件内容作为已理解的证据。

## 主题模板

下例为占位模板。发布前用实际内容、时间和计算得到的哈希替换所有占位符；删除不适用的结论与空章节。状态由实际内容决定。

```markdown
---
schema: kiokunet.shared/v1
title: "<主题名称>"
updated: "<实际修订时间，ISO 8601，带时区>"
status: needs-review
---

# <主题名称>

## 当前结论

- 用户已确认：<有明确确认依据的结论及适用范围>。[S1]
- Agent 推断：<尚未确认的推断及适用范围>。[S2]

## 待核实

<双方分歧、各自来源编号，以及尚待确认的问题。>

## 来源

| 编号 | 来源目录 | 相对路径 | 提炼时 SHA-256 | 读取时间 | 当前可用情况 |
| --- | --- | --- | --- | --- | --- |
| S1 | <实际来源> | <相对 raw 的路径> | <实际64位十六进制哈希> | <实际读取时间> | <可用情况及检查时间> |
| S2 | <实际来源> | <相对 raw 的路径> | <实际64位十六进制哈希> | <实际读取时间> | <可用情况及检查时间> |
```

## 发布前检查

完成以下检查后，按主 Skill 的原子替换和索引最后更新流程发布：

1. YAML 语法、字段语义和状态值符合上述约定；新修订使用实际带时区时间，标题与正文一致。
2. 每条结论对应明确来源编号，确认程度与证据相符；来源哈希与读取记录一致，未知或失效依据有明确说明；模板占位符全部替换。
3. 主题间与索引中的相对链接可解析到实际文档；分歧、适用范围和替代关系在正文中可见。
4. 只修改本轮需要更新的 Shared 文档与索引，保留 Raw 自由格式和已有无头部文档的可读性。

这些检查由执行 Skill 的 Leader 完成，CLI 当前不解析或强制校验该 schema；格式合格不等于事实已验证。
