# Shared 输出约定与模板

这是 `kioku-curate` 的默认输出约定。新建或实质更新 Shared 文档时采用；已有文档继续可读，格式升级不触发全库重写。Raw 的文件名、目录和正文保持自由，不要求记录 ID、元数据头或追加日志。

## 主要归属与内容筛选

默认提供三个基础目录，按内容所描述的对象归类：

| 目录 | 内容与边界 |
| --- | --- |
| `profiles/` | 用户基础信息、经历，以及健康、爱好、财务等长期跟踪内容。交易事实、健康事件属于个人记录，不因重复发生就成为偏好。 |
| `projects/` | 用户相关项目。每个项目自第一篇内容起就使用 `projects/<项目>/`，其中维护背景、当前状态、决定及有价值的过程记录。单个项目的约束留在项目内。 |
| `prefers/` | 用户的长期规则、稳定习惯和决策偏好，正文说明适用场景及必要的例外。 |

这三个目录是基础模板，不是穷尽分类。独立研究或跨项目参考知识确实无法归入三者时，可按需新增有明确用途的目录。沿用已有合适分类，避免为一次零散材料新建顶层类别。

先筛选再归类：保留能帮助未来行动的事实、决定及理由、重要沟通结果、可复用的调用方法和影响后续工作的失败原因。普通读取、搜索、重试、渲染测试等流水留在 Raw；没有新信息的重复材料不再生成一份结论。助手提出但用户未采纳的建议不能变成用户决定。

每篇文档围绕一个连贯主题。按用户、项目或知识主题综合多个来源；同一结论保留一个主要位置，其余位置通过普通 Markdown 相对链接引用。内容粒度以能独立理解和按需读取为准，主题明显分化时再拆分，避免跨项目年度大日志和一条事实一个文件。

## 目录与渐进索引

每个知识目录都有 `Index.md`，统一使用这一大小写；新增子目录时同时建立索引。三个基础目录之外的子目录与具体文件按内容需要创建。

| 索引 | 应让读者直接获得的理解 |
| --- | --- |
| `shared/Index.md` | 知识库概览及各类入口。 |
| `profiles/Index.md` | 已知的基础信息，例如用户名、别名、出生日期、兴趣概览；详细爱好、健康等内容通过链接展开。 |
| `projects/Index.md` | 项目列表，每项简述用途或状态并链接项目首页。 |
| `projects/<项目>/Index.md` | 项目背景、功能、当前状态及已知的仓库或线上地址；链接具体决定、沟通和调用记录。 |
| `prefers/Index.md` | 常用规则的简短概要及适用场景，链接详细偏好。 |
| 其他子目录的 `Index.md` | 当前主题的简短概况及直接子项入口。记录目录按日期列出事件和意义。 |

按 `根概览 → 目录概览 → 具体知识 → 必要证据` 渐进读取。索引包含足以理解本层的概要，不复制全部下级正文；每个链接说明内容或何时阅读。只链接实际存在的目标。

个人与项目首页只写有依据的信息，删除不适用的空章节，不为模板字段堆积“未知”“未提供”。索引中的概要可链接承载依据的具体正文；独立记录事实的索引同样使用下述元数据和来源表，纯导航索引可省略二者。整理统计、同步故障等运行流水保存在运行进度中。

示例结构如下，除基础目录外仅在有对应内容时创建：

```text
shared/
├── Index.md
├── profiles/
│   ├── Index.md
│   ├── hobbies.md
│   └── health/
│       ├── Index.md
│       └── training.md
├── projects/
│   ├── Index.md
│   └── kiokunet/
│       ├── Index.md
│       ├── decisions.md
│       └── records/
│           ├── Index.md
│           └── 2026-10-18-shared-organization.md
└── prefers/
    ├── Index.md
    ├── communication.md
    └── development.md
```

Shared 以根索引为入口，工作区阅读指引由维护者选择配置，不额外生成重复的 `MEMORY.md` 或运行器指令文件。

## 偏好提炼

明确表达长期适用的要求，一次即可沉淀；例如“以后都用中文回复”。“这次用中文”只适用于该次任务。

从行为归纳偏好，至少需要两个独立场景的同向证据，再检查是否只是临时限制或项目约束。多个 Agent 转述同一次选择只算一次证据；达到次数并不自动说明偏好成立。正文写清适用范围，用“在……场景中通常选择……”表达观察结果，并引用支撑它的来源。

用户明确纠正偏好时，更新对应的当前规则及索引摘要。单次例外先按其情境理解，不能自动覆盖长期规则；单项目决定也不能升级为全局偏好。仍有实质歧义时，在相关条目旁说明具体不确定性。

## 当前概要与日期记录

首页和主题正文维护当前有效结论；新事实补充、纠正或替代旧结论时直接修订对应内容。比较事实发生时间、适用场景、版本和证据，不能仅凭文件更新时间或处理先后决定哪条为准。

有复用价值的过程按日期记录：短记录可在对应主题下按事件日期递增追加；独立沟通或调用事件放入项目的 `records/YYYY-MM-DD-事件.md`。日期来自事件本身，时间不明时使用描述性文件名并说明事件时间未知，不把整理日期冒充发生日期。同一事件的新材料合并到原记录，不因再次整理而重复追加。

记录写清背景、决定或结果、理由及对后续工作的影响。历史选择用当时的日期和语境表达；已替代的决定链接当前结论。只保留对理解变化有价值的过程，不为每次编辑保存旧正文副本。调用记录保留可复用步骤与关键结果，原始输出按需引用来源。

## 旧库兼容

已有 `INDEX.md`、`profile/`、`topics/` 及无头部文档继续可读。常规增量整理沿用旧库实际入口，并使本轮涉及的新目录、概要和链接符合本约定；仅模板更新不触发整库改名或批量重组。

用户要求重组时，按内容语义映射旧文档，先发布目标文档、修复引用并更新各级索引，确认原有信息与依据已妥善归属后再清理被替代文件。大小写切换须兼顾大小写不敏感的文件系统：使用临时名完成改名并核对实际目录项，不创建仅大小写不同的两份索引。保留已有扩展目录；不能将旧 `topics/` 全部机械改为 `prefers/`。

## 主题文档元数据

使用 YAML 头，默认四个字段：

| 字段 | 写入规则 |
| --- | --- |
| `schema` | 固定为 `kiokunet.shared/v1`，表示此输出约定的版本。 |
| `title` | 人可读主题名，与正文一级标题一致。 |
| `updated` | 最近一次实质修订的实际时间，ISO 8601 并带时区；纯格式调整保留原时间。 |
| `status` | `current`：可供当前使用；`needs-review`：存在影响使用的冲突或待核实事项；`superseded`：结论已被替代，正文链接当前文档或说明替代结论。 |

`current` 不代表所有结论都经过用户确认。`updated` 不代替事实发生时间、适用版本或来源读取时间；有时间边界的结论在正文注明适用范围。无必要不增加稳定 ID、标签或有效期字段。保留既有有意义的扩展字段，不把来源自称的身份或信任等级当成可信凭据。

## 结论与来源

每条可独立使用的结论引用来源编号，直接写事实或规则，不加“用户已确认”“来源直接陈述”等机械前缀。推断、建议和实质冲突在相关内容旁用自然语言说明，不能把移除标签理解为消除不确定性，也不能以整理者的判断代替用户决定。

比较适用项目、时间、环境与确认程度处理冲突。文件修改较晚不代表结论更权威。无法消解时保留双方观点、对应来源和待核实问题，并设为 `needs-review`。

来源表统一保存在正文，每条来源记录：

- 来源目录及相对该目录 `raw/` 的路径，由实际读取位置和来源登记确定。
- 提炼时读取并确认稳定的内容 SHA-256，使用完整 64 位十六进制值。
- 读取该内容的实际时间（带时区），以及最近检查时的可用情况。

来源坐标为 `<来源目录>/raw/<相对路径>`，不是 Hub 绝对路径。普通 Agent 未必能访问其他 Raw，来源表用于核对与请求 Leader 复核，不伪装成所有节点可打开的链接。网页证据附实际 URL 和检索日期；经 Raw 转述时同时保留 Raw 来源。

哈希仅标识当时读到的内容，不是签名、置信度或历史恢复地址。保留已有结论时保留其原有来源哈希与读取时间；重新评估新内容后才更新相应证据。来源当前变化或不可用时写明情况及检查时间，不能用新哈希替换旧证据后仍声称旧结论已被验证。旧文档缺少历史哈希或读取时间时标为未知，待实际读取复核后补齐，不能编造。

来源删除不自动撤回结论；结合剩余依据决定保留、修订或标为待核实。未解析附件只记录其存在、路径与未解析状态，不把附件内容作为已理解的证据。

## 主题模板

下例为占位模板。发布前用实际内容、时间和计算得到的哈希替换所有占位符；删除不适用的结论与空章节。状态由实际内容决定。

```markdown
---
schema: kiokunet.shared/v1
title: "<主题名称>"
updated: "<实际修订时间，ISO 8601，带时区>"
status: needs-review
---

# <主题名称>

## 当前结论

- <当前事实或规则及其适用范围>。[S1]
- <根据来源观察到的倾向及适用场景；仅在有价值且有依据时保留>。[S2]

## 详情

- [<子主题名称>](<实际相对路径>)：<内容简介或何时阅读>。

## 待核实

<双方分歧、各自来源编号，以及尚待确认的问题。>

## 来源

| 编号 | 来源目录 | 相对路径 | 提炼时 SHA-256 | 读取时间 | 当前可用情况 |
| --- | --- | --- | --- | --- | --- |
| S1 | <实际来源> | <相对 raw 的路径> | <实际64位十六进制哈希> | <实际读取时间> | <可用情况及检查时间> |
| S2 | <实际来源> | <相对 raw 的路径> | <实际64位十六进制哈希> | <实际读取时间> | <可用情况及检查时间> |
```

## 发布前检查

完成以下检查后，按主 Skill 的原子替换和索引最后更新流程发布：

1. YAML 语法、字段语义和状态值符合上述约定；新修订使用实际带时区时间，标题与正文一致。
2. 每条结论有来源支持，推断与实质冲突用自然语言明确；来源哈希与读取记录一致，未知或失效依据有明确说明；模板占位符与不适用的空章节全部删除或替换。
3. 内容有明确的主要归属，项目文档位于各自项目目录，偏好符合独立证据与适用范围规则；重复流水不进入长期知识。
4. 新建知识目录有 `Index.md`；受影响的各级索引同时更新，概要能独立提供本层理解，所有相对链接可解析到实际目标。旧库按兼容规则处理。
5. 当前概要与历史事件清晰区分，实质分歧、时间范围和替代关系可见；日期追加没有重复提升同一事件。
6. 只修改本轮需要更新或用户指定重组的 Shared 范围，保留 Raw 自由格式和旧文档的可读性。

这些检查由执行 Skill 的 Leader 完成，CLI 当前不解析或强制校验该 schema；格式合格不等于事实已验证。
