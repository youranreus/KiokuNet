# shared 只读副本与工作区防误写

用户希望普通 Agent 不误写公共知识，同时保持现有运行器和轻量目录接入。决定用自动生成的 shared 只读副本作为普通 Agent 工作区链接目标，取消独立系统账号和源目录访问隔离的强制校验；真实 shared 保持同步可写，Hub 上的 Leader 直接链接并维护本体。自己的 Raw 保持可写，Leader 可额外配置全部 Raw 入口。只读副本防止正常文件操作误写，不承诺阻止所有者改权限、访问真实路径或其他主动绕过。

选择副本而非直接 chmod 源目录，是为了避免影响同账号同步服务；相较 Linux/macOS 只读挂载，不强制管理员权限或文件系统组件，代价是空间、短暂刷新延迟和副本维护。后台在 shared 更新后自动刷新；失败保留最后成功副本并展示错误及更新时间，恢复后继续刷新，不能降级链接可写本体。首次无可用副本时接入报错。副本不是历史备份或恢复点。

本决策取代 ADR 0004 的强制独立账号、POSIX 权限隔离及 Leader 对其他 Raw 的强制只读校验，保留链接冲突保护、解除接入保留数据、自由编辑 Raw 和不管理 Agent 执行的边界。CLI 不修改提示词或创建提炼任务。方案对比、目录布局及验证边界见 [设计记录](../2026-10-16-machine-and-agent-access-design.md)；本决策已实现，验证范围见 [实现记录](../implementation.md)。
