## 两个使用视角

机器负责保存和同步知识，Agent 通过工作区入口使用知识。机器入网、来源登记和工作区接入是三个独立操作；安装 Hub 或其他节点时可以没有任何 Agent。

Hub 汇集全部来源 Raw，并分发 shared。其他节点保存本机来源 Raw 和 shared，不是全网 Raw 的完整镜像。首版 Leader 在 Hub 机器上运行，直接读取汇集资料并维护 shared；Hub 安装时不必同时创建 Leader。

普通 Agent 的 Raw 入口指向自己的来源目录，shared 入口指向自动更新的只读副本。Leader 的 Raw 入口同样指向自己的来源目录，shared 入口直接指向可写本体，并可额外配置全部 Raw 的入口。两者采用相同的工作区链接机制，按用途选择不同目标。

## 安装根目录

默认安装根目录为 `~/.kiokunet`，用户可以整体配置为 `/opt/kiokunet` 等路径。Hub 和其他节点采用同一约定。

| 内容 | 目标位置或约定 |
| --- | --- |
| 知识库本体 | `<安装根>/data/` |
| 配置、设备凭据 | `<安装根>/config/` |
| 普通 Agent 使用的 shared 只读副本 | `<安装根>/views/shared/` |
| 同步状态、日志、缓存、下载的依赖等持久文件 | 统一放在安装根目录内；具体子目录名由实现确定 |
| 系统服务注册文件 | 允许放在系统要求的位置，引用安装根目录内的文件 |
| 工作区链接 | 放在用户选择的 Agent 工作区入口位置 |
| CLI 程序本体 | 由包管理器安装，不要求移动到安装根目录内 |

知识内容布局保留如下；配置路径与 CLI 参数见 [使用指南](usage.md)：

```text
<安装根>/
├── data/
│   ├── agents/<来源标识>/raw/
│   └── shared/
├── config/
└── views/
    └── shared/
```

安装根目录、知识库本体和工作区入口是不同概念。路径变更应整体遵循新的安装根目录，不能仅修改 data 而把配置、状态等遗留在默认位置。

## 机器入网与来源登记

1. 在云机安装 Hub，配置安装根目录及 IP、端口等连接参数，建立网络和基础设施。
2. 在 Mac 或其他机器安装节点，通过机器邀请与回执完成配对。设备身份和网络信任不再依附于某个 Agent 来源。
3. 已入网机器创建新来源时，无需重新交换邀请、回执或要求 Hub 逐个批准；后台向 Hub 登记来源并建立同步关系。
4. 允许在已入网机器离线时创建来源并写本地 Raw，联网后自动完成登记和同步。状态应区分本地已创建与网络登记、同步已完成。
5. 一个来源同时只有一台写入机器。新增来源不能接管其他机器已经持有的来源身份。

来源属于长期助手的知识归属，不能按新会话、项目名或运行器名称自动新建或猜测。首次使用通过 CLI 创建来源，以后接入工作区时选择已有来源；同一台机器上的多个工作区可以共用同一个来源，所有 Raw 入口指向同一份数据。

## 工作区接入边界

| 使用者 | 自己的 Raw | shared | 全部 Raw |
| --- | --- | --- | --- |
| 普通 Agent | 链接来源目录，可读写 | 链接只读副本，防误写 | 不默认提供 |
| Hub 上的 Leader | 链接来源目录，可读写 | 链接真实 shared，可读写 | 可额外配置汇集目录入口 |

CLI 管理链接的创建、目标检查、冲突检查和解除。已有不同内容时拒绝覆盖；相同映射可以重复接入。解除接入只删除已登记且仍匹配的链接，保留来源数据；停用来源和机器退网是独立操作。

取消独立无特权系统账号作为接入前提，不再强制验证普通 Agent 的源目录访问隔离或 Leader 对其他 Raw 的只读权限。只读副本提供正常文件操作下的防误写，不阻止同账号所有者主动改权限、访问真实路径或替换工作区入口。来源归属和单写入约束也不等于操作系统访问隔离。

接入不会修改提示词、工作区规则、启动 Agent 或创建提炼任务。普通 Agent 不必安装 memory Skill，不需在文件操作时绑定身份或调用 context。Leader 可以继续使用独立的 curate Skill；Agent 执行和调度仍由现有运行器负责。

## shared 只读副本

真实 shared 保持同步服务所需的可写性，Hub 上的 Leader 直接维护这份真实数据。普通 Agent 通过工作区链接读取本机的派生副本；同机普通 Agent 可以共用这份副本。

只读副本同时约束文件内容写入与目录项的创建、删除、替换，不能仅把文件设为不可写却留下可写父目录。副本不与真实 shared 共用硬链接文件；更新副本也不能把源目录改成只读，否则会干扰同账号同步服务和 Leader 写入。

本机收到 shared 同步更新，或本机 Leader 修改 shared 后，由 KiokuNet 后台基础设施自动刷新副本。工作区入口保持稳定，允许短暂刷新延迟，不需要重新接入或 Agent 配合。刷新和知识提炼是两件事，前者不启动 Agent。

| 场景 | 已确认行为 |
| --- | --- |
| shared 更新且刷新成功 | 普通 Agent 经原有入口读取更新后的副本 |
| 同步中断、离线或副本刷新失败 | 保留最后成功副本，已有知识继续可读 |
| 副本刷新失败 | CLI 状态展示失败与最后成功更新时间，不切换到可写本体 |
| 首次接入没有可用副本 | 明确报错，不以空目录冒充成功接入 |
| 故障恢复 | 后台自动继续刷新 |

实现应先准备新的只读副本，再切换稳定入口，避免在当前可见副本上临时开放写权限。当前后台每秒检查内容变化，复制校验后原子切换入口，保留当前及上一代副本，清理更早副本。不得据此承诺跨节点多文件事务一致性。副本只是当前内容的派生数据，不新增历史备份或恢复功能。

## 只读方案调研与取舍

下表为本次调研结论；只读挂载后端未进行本项目实机验收。

| 方案 | 能力与代价 | 本轮结论 |
| --- | --- | --- |
| 对真实 shared 修改 chmod / ACL 后再链接 | 同一用户、组下不能仅凭进入路径区分 Agent 和同步服务；目录不可写会影响同步，所有者仍可恢复权限 | 不采用 |
| 只读副本加工作区链接 | 阻止正常文件操作误写，不改源数据权限；增加空间、刷新延迟和副本管理，不提供主动绕过防护 | 采用 |
| Linux 只读 bind mount | 挂载入口只读，原目录仍可写；通常需要管理员权限和挂载生命周期管理，原路径访问仍需另行限制 | 不作为首版接入要求 |
| macOS FUSE 只读映射 | 能提供只读挂载入口，但增加组件安装、后台进程和平台兼容维护 | 不作为首版接入要求 |
| 不同系统账号与权限隔离 | 可以建立更强的访问边界，但必须确保 Agent 实际使用指定账号 | 撤销原强制前提 |
| Agent 沙箱或容器 | 可由运行环境限制写入，但需要适配或改变 Agent 启动方式 | 不作为通用接入前提 |
| Syncthing receiveonly | 限制本地修改向外传播，不阻止本地文件修改 | 保留其同步用途，不视作只读权限 |

临时目录实验验证了三个行为：通过链接修改目标文件权限会作用于源文件；文件不可写但父目录可写时仍可替换文件；目录不可写时普通创建操作失败。实验未修改项目知识数据，当时的实验仅证明权限行为；后续后台刷新验证见实现记录。

调研依据（2026-10-16 查阅）：

- [Linux symlink 手册](https://www.man7.org/linux/man-pages/man7/symlink.7.html)：普通符号链接的权限不提供目标内容的独立只读限制。
- [Linux chmod 手册](https://man7.org/linux/man-pages/man2/chmod.2.html)：权限作用于目标文件，文件所有者可以修改权限。
- [Apple 文件系统权限说明](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemDetails/FileSystemDetails.html)：ACL 按用户、组等身份评估访问。
- [Linux mount 手册](https://www.man7.org/linux/man-pages/man8/mount.8.html)：只读 bind mount 可以保留原目录可写。
- [bindfs 项目说明](https://bindfs.org/)与[只读选项](https://bindfs.org/docs/bindfs.1.html)：提供只读映射，macOS 支持和兼容性存在维护限制。
- [macFUSE 安装说明](https://github.com/macfuse/macfuse/wiki/Getting-Started)：有 FSKit 与内核后端，不能笼统认为所有方案都需开启内核扩展。
- [Docker bind mount 文档](https://docs.docker.com/engine/storage/bind-mounts/)：容器可以获得只读挂载入口，但涉及 Agent 运行环境。
- [Syncthing 文件夹类型](https://docs.syncthing.net/users/foldertypes.html)：receiveonly 允许本地修改，只是不向外传播这些修改。
